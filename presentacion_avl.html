El Problema de los ABB

Los Árboles de Búsqueda Binaria (ABB) NO garantizan un acceso rápido en todos los casos.

  • Inserciones de datos ya ordenados crean árboles desequilibrados.
  • En el peor caso, la búsqueda pasa de O(log n) a O(n) (lineal), comportándose igual que una lista enlazada defectuosa.

Ejemplo: Inserta en un ABB los números: 7, 5, 3, 1

¿Qué es un Árbol AVL?

Es un tipo especial de Árbol Binario de Búsqueda que se auto-balancea.

  • Garantiza que la búsqueda, inserción y eliminación siempre tomen un tiempo O(log n).
  • Fue inventado por Adelson-Velsky y Landis (de ahí sus siglas AVL).
  • Utiliza una propiedad matemática estricta basada en la Altura para aplicar "rotaciones" automáticas si detecta un desequilibrio.

Altura y Factor de Equilibrio

Para que el árbol se auto-gestione, cada nodo rastrea su Altura.

Fórmula del Equilibrio

Balance = Altura(Izq) - Altura(Der)

  • Permitidos: -1, 0, +1. (El nodo está balanceado).
  • Críticos: +2 o -2. (El nodo se desbalanceó y exige una rotación inmediata).

El Proceso de Inserción

El proceso de inserción en un AVL se realiza en dos pasos fundamentales:

Paso 1: Inserción Tradicional

Se realiza la inserción siguiendo el esquema estudiado para los ABB. De esta forma, el nuevo nodo queda colocado como una hoja del árbol.

Paso 2: Backtracking y Rotación

Se recorre el camino de regreso hacia la raíz (recursión hacia atrás), actualizando los equilibrios por el camino.

Si se encuentra un nodo durante este recorrido cuyo equilibrio pase a ser +2 ó -2, entonces se ajustan los subárboles (Rotación), de tal forma que el árbol se convierta nuevamente en un ABB con equilibrio 0, +1 ó -1 en cada nodo.

Las 4 Rotaciones de AVL

Dependiendo de cómo se formó el desbalance (el patrón de la inserción), el AVL aplica una u otra rotación de los punteros:

1. Rotación Derecha (Simple)
Ocurre cuando el desbalance es en línea recta hacia la izquierda (Caso LL: Izquierda-Izquierda).
2. Rotación Izquierda (Simple)
Ocurre cuando el desbalance es en línea recta hacia la derecha (Caso RR: Derecha-Derecha).
3. Rotación Izquierda-Derecha (Doble)
Desbalance en forma de Zig-Zag (Caso LR). Primero se rota el hijo a la izquierda, y luego el padre a la derecha.
4. Rotación Derecha-Izquierda (Doble)
Desbalance en Zig-Zag (Caso RL). Primero rota el hijo a la derecha, luego el padre a la izquierda.

Código: Inserción con Balanceo

El método de inserción incluye un Paso 2 para recalcular la altura y balancear.

private NodoAVL<T> insertarRecursivo(NodoAVL<T> nodo, T valor) {
    // 1. Inserción clásica de ABB
    if (nodo == null) return new NodoAVL<>(valor);
    if (valor.compareTo(nodo.dato) < 0) nodo.izquierdo = insertarRecursivo(nodo.izquierdo, valor);
    else if (valor.compareTo(nodo.dato) > 0) nodo.derecho = insertarRecursivo(nodo.derecho, valor);
    else return nodo; // No se permiten duplicados

    // 2. Actualizar altura del ancestro actual
    nodo.altura = 1 + max(obtenerAltura(nodo.izquierdo), obtenerAltura(nodo.derecho));

    // 3. Obtener Factor de Balance
    int balance = obtenerBalance(nodo);

    // 4. Si el nodo se desbalancea, probamos los 4 casos de Rotación
    if (balance > 1 && valor.compareTo(nodo.izquierdo.dato) < 0) // Caso Izquierda-Izquierda
        return rotacionDerecha(nodo);
    
    // ... (Se manejan los casos Derecha-Derecha y los casos Zig-Zag)
    
    return nodo;
}

Código: Rotación Simple (Derecha)

Así es como se reasignan los punteros en tiempo O(1).

private NodoAVL<T> rotacionDerecha(NodoAVL<T> y) {
    // Definimos los punteros temporales
    NodoAVL<T> x = y.izquierdo;
    NodoAVL<T> T2 = x.derecho;

    // Realizamos la rotación (Intercambio)
    x.derecho = y;
    y.izquierdo = T2;

    // Actualizamos las alturas (primero el hijo, luego el padre)
    y.altura = max(obtenerAltura(y.izquierdo), obtenerAltura(y.derecho)) + 1;
    x.altura = max(obtenerAltura(x.izquierdo), obtenerAltura(x.derecho)) + 1;

    // Devolvemos la nueva raíz de este subárbol
    return x;
}

Orden Espacial y Temporal (Big O)

En un Árbol AVL, el auto-balanceo cambia las reglas del juego y nos asegura que no existe un peor caso lineal.

Operación Peor Caso en AVL Peor Caso en ABB Normal
Búsqueda O(log n) O(n)
Inserción O(log n) O(n)
Eliminación O(log n) O(n)
Orden Espacial: O(n). Requiere almacenar el valor, los dos punteros y la variable de altura por cada nodo. ¡Consume un poco más de memoria que un ABB normal a cambio de rendimiento estricto!

¿Cuándo usar AVL y cuándo no?

✅ CUÁNDO USAR AVL

  • Cuando las búsquedas son muchísimo más frecuentes que las inserciones o eliminaciones.
  • Cuando necesitas garantizar estrictamente un tiempo de respuesta de O(log n) en bases de datos en memoria o sistemas en tiempo real.

❌ CUÁNDO NO USARLO

  • Si hay demasiadas inserciones y eliminaciones constantes (el costo matemático de rotar a cada rato es altísimo). En la industria, para esos casos se prefiere usar un Árbol Rojo-Negro (Red-Black Tree).

Errores Comunes en el Código

  • Olvidar actualizar la Altura: No recalcular la altura de un nodo después de insertar o de rotar. Esto destruye la fórmula de equilibrio para los siguientes niveles.
  • Orden invertido en Rotación Doble: Aplicar una Rotación Doble al revés (rotar el padre primero en vez del hijo). Recuerda: siempre se rota primero al hijo para "enderezar el zig-zag".
  • Confundir +2 con -2: Si tu fórmula es Altura(Izq) - Altura(Der), el +2 significa pesadez a la izquierda. Poner los if al revés creará un bucle infinito de rotaciones erróneas.

Conclusiones Finales

El Árbol AVL intercambia un pequeño costo en inserción (calcular rotaciones) por un rendimiento absoluto y garantizado en búsquedas.

"El balance previene el caos lineal."
